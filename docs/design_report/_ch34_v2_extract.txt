26|Heading 3|2.3 关键技术选型
27|Heading 3|（1）智能体注册与发现
28|List Bullet|六体各自 ACS 入驻，平台发证后 AIC=证书 CN 回填运行环境。
29|List Bullet|采购以**改写后的完整需求句**（可含多品）调用 ADP；`discover_suppliers_for_brief` 对 `brief.items[]` 做 **SKU 并集召回**，避免「脚轮+坐垫」只命中一家品类。
30|List Bullet|发现结果进入短名单 UI；**断点①**前人不得自动发 RFQ / 自动开群。
31|Heading 3|（2）跨智能体数据传输
32|List Bullet|**点对点**：`v2.initial_quote` / `v2.bargain` / `v2.promo_query` / `v2.place_order` / `v2.logistics_quote` 等结构化信封。
33|List Bullet|**组群**：采购主持 `open_group` → 成员 join → 群内按行 `v2.group_bid`；失败可 `force_local` 续跑，但不得伪称 `transport=group`。
34|List Bullet|**效力字段**：共享 `order_id` / `logistics_id`；供应工具仅当 `place_order=on` 落单。
35|Heading 3|（3）协同调度（业务状态机）
36|List Bullet|**硬编排**：`Phase` 状态机（`SHORTLIST_PENDING` → … → `GROUP_DECIDE` 等）决定合法迁移。
37|List Bullet|**软入口**：对话只触发已注册路径函数；AskUser 挂起等人；Gate 为工单页写 ack。
38|List Bullet|**普通路径**：改写 → 发现 → 短名单 → 初报 → 议价 Ask → 买法 → 下单 Gate → 物流。
39|List Bullet|**组群路径**：冲突建议 →「我要组群竞价」→ 勾选成员 → 主持开群 → 按行报价 → 全量覆盖方案 → 拆单工单。
40|Heading 3|（4）安全交互与鉴权
41|List Bullet|默认平台证书 + mTLS；组群邀请跨云自签场景可配置关闭校验（工程开关，材料中如实说明）。
42|List Bullet|工单确认以 `buyer_ack`/`supplier_ack`/`effective` 为准；物流 Gate 使用 logistics ticket id。

70|Heading 2|1. 项目背景与需求
71|Heading 3|1.1 业务背景
72|Normal|智能办公家具场景下，座椅原料（脚轮、面料、坐垫等）需跨企业完成「寻源—议价—下单—物流」闭环。传统方式依赖人工多轮询价；本作品将流程交由多智能体按 AIP 国标互联，并在关键节点保留人确认。
73|Heading 3|1.2 建设目标（可验收）
74|List Number|**梧桐全链路**：六体入驻发证、ADP 发现、AIP/组群交互、AMP 访问统计可查。
75|List Number|**双路径业务**：普通采购询价与采购主持组群竞价均可端到端跑通。
76|List Number|**人在环效力**：短名单/议价/买法/组群确认用 AskUser；订单与物流用 Gate 工单 ack。
77|List Number|**多品全覆盖**：一次需求含脚轮+坐垫等时，发现并集、组群按行报价、汇总不漏项。
78|List Number|**双云真实部署**：腾讯采购侧与阿里供应侧分域运行，控制台 HTTPS 可访问。
