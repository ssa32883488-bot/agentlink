# 四、智能体互联项目实施

> 对应大纲「四、智能体互联项目实施」。  
> 实施对象：commerce_v2 双路径采销协同（腾讯采购云 × 阿里供应云）。  
> 验收证据目录示例：`docs/evidence/v2_dual_20261030_194944/`。

---

## 1. 项目背景与需求

### 1.1 业务背景

智能办公家具场景下，座椅原料（脚轮、面料、坐垫等）需跨企业完成「寻源—议价—下单—物流」闭环。传统方式依赖人工多轮询价；本作品将流程交由多智能体按 AIP 国标互联，并在关键节点保留人确认。

### 1.2 建设目标（可验收）

1. **梧桐全链路**：六体入驻发证、ADP 发现、AIP/组群交互、AMP 访问统计可查。  
2. **双路径业务**：普通采购询价与采购主持组群竞价均可端到端跑通。  
3. **人在环效力**：短名单/议价/买法/组群确认用 AskUser；订单与物流用 Gate 工单 ack。  
4. **多品全覆盖**：一次需求含脚轮+坐垫等时，发现并集、组群按行报价、汇总不漏项。  
5. **双云真实部署**：腾讯采购侧与阿里供应侧分域运行，控制台 HTTPS 可访问。

### 1.3 需求边界

| 纳入 | 不纳入（本期） |
|------|----------------|
| 结构化询价/议价/下单/物流信封 | 真实支付与仓储 WMS |
| 国标组群优先 + 可声明的本地降级 | 改写 Wit 旧主路径作为默认演示 |
| LLM 需求改写 | 模型口头下单生效 |
| 六体独立库与工单 | 跨域直连对方数据库 |

## 3. 关键技术实施

### 3.1 智能体注册与发现

**步骤**

1. 为六体准备 ACS 描述并在梧桐入驻；下载证书，AIC=证书 CN 写入各体环境。  
2. 采购侧配置 Discovery URL（`acps-adp-v2/discover`）。  
3. 用户输入需求 → `llm_rewrite` 产出 `rewritten` + `items[]`。  
4. `discover_suppliers_for_brief`：对每个 SKU 检索后做供应并集，写入短名单。  
5. UI 展示候选；用户点「确认并询价」或「我要组群竞价」后方可出网。

**验收点**：返回体含 `platform_adp` 或诚实标注降级来源；多品需求下短名单覆盖相关品类供应。

### 3.2 跨智能体数据传输

**点对点（普通路径）**

| 信封 schema | 方向 | 作用 |
|-------------|------|------|
| `v2.initial_quote` | 采→供 | 初报 |
| `v2.bargain` / `v2.promo_query` | 采→供 | 议价/优惠 |
| `v2.place_order`（`place_order=on`） | 采→供 | 落单 |
| `v2.logistics_quote` 等 | 采→物 | 运力方案 |

**组群**

1. 采购主持调用开群（`group_mq`）；成员以证书身份 join。  
2. 群内按目录能力发送 `v2.group_bid`；物流合入运力。  
3. 前端组群聊天室展示过程；结束后可折叠为摘要条。  
4. `transport=group` 仅在真实国标通道成功时标记。

**共享标识**：订单/物流 id 写入双方工单，Gate 双边 ack 后标 `effective`。

### 3.3 协同调度实施

**普通路径实施顺序（与 UI 断点对齐）**

1. 改写与发现 → 短名单 AskUser  
2. 并行初报 → 是否探优惠 AskUser  
3. 可选议价 → 买法 AskUser  
4. 工具闸 `place_order=on` → 订单 Gate  
5. 人确认后询运 → 物流 Gate  

**组群路径实施顺序**

1. 冲突/复杂建议 →「我要组群竞价」  
2. 勾选供应±物流 →「确认组群竞价」  
3. 开群与按行出价 → 全量覆盖方案决断  
4. 拆单工单系列确认  

**调度原则**：Phase 非法迁移拒绝；对话不直接写效力字段。

### 3.4 安全交互与鉴权实施

1. 生产默认校验证书链；组群跨云自签时使用约定工程开关并在材料中披露。  
2. Partner 校验来访任务与 AIC 绑定。  
3. 供应侧拒绝无 `place_order=on` 的落单请求。  
4. 控制台：采购/物流可用 HTTP 或 HTTPS；**供应 UI 强制 HTTPS**，避免浏览器「网络错误」。

### 3.5 人机与工单实施

| 能力 | 实现要点 |
|------|----------|
| AskUser | `choice_actions` 渲染为按钮；短名单确认组件 |
| Gate | `/tickets` 列表；`ack-order` / `ack-logistics` |
| 组群室 | 置顶可折叠；按消息流展示出价 |
| 清理 | `scripts/_clear_history_and_tickets.py` 演示前清场 |

## 4. 实施过程与里程碑

| 阶段 | 工作内容 | 结果 |
|------|----------|------|
| M1 协议底座 | ACS/AIC、ADP、AIP、AMP、双云 systemd | 六体可发现可调用 |

- 组群 SSL 邀请在自签环境可配置信任策略。  
- 多品改写防幻觉与发现并集，避免坐垫漏项。  
- 组群聊天室可收起，避免占满对话区。  
- 供应控制台改 HTTPS 消除跨站/混合内容类网络错误。

## 6. 与梧桐平台对接说明（材料表述）

1. **注册**：六 ACS 入驻，证书落地，AIC 回填。  
2. **发现**：采购以改写需求调用平台 Discovery。  
3. **互联**：HTTPS `/rpc` 承载 AIP Task；组群走平台 MQ 通道。  
4. **访问**：Leader/Partner 写 Kafka 主题，作品材料附平台访问量截图。  

对接原则：**协议平面跟国标与平台；业务平面用 commerce_v2 自研编排**——二次开发边界清晰，便于评审查验。

---

## 7. 实施总结

本项目在 AIP/ACPs 与梧桐通道上完成工业采销多智能体互联落地：以 commerce_v2 确定性双路径替代不可控的工具乱序调用；以 AskUser/Gate 保证人在环效力；以多品并集与组群按行出价保证复杂需求可覆盖；以双云六体证明跨企业可部署。后续可在不改国标骨架前提下扩展更多品类 ACS、加强组群失败自动恢复策略，以及把访问统计看板嵌入控制台。
